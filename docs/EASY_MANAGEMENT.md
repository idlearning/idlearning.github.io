# 홈페이지 콘텐츠 관리 가이드 (구글 시트/폼)

이 사이트의 **People / Projects / Publications / News** 콘텐츠는 코드를 건드리지 않고
**하나의 구글 시트**로 관리합니다. 시트를 수정하면 정해진 주기(기본 1시간)마다 자동으로,
또는 원할 때 수동으로 사이트에 반영됩니다.

동작 원리 요약:

```
구글 시트 ─▶ (링크 공개 CSV) ─▶ scripts/sync-sheets.mjs ─▶ src/data/generated/*.json ─▶ 빌드/배포
 ├ People, Projects            (손으로 편집)        │
 ├ Pub-Manual + Pub-Form       ─┐                   │ 여러 탭을 합치고, id·정렬·뉴스 URL·
 └ News + News-Form            ─┴─ 코드가 직접 합침  │ 날짜 형식 정리를 모두 여기서 처리
```

**원칙: 시트에는 입력만, 가공은 코드가.** 시트 안에 탭을 합치는 수식(QUERY/SORT/VLOOKUP)은
필요 없습니다. 폼 응답 탭도 sync가 직접 읽습니다.

> ⚠️ 정적 사이트라 시트 수정이 **즉시** 반영되지는 않습니다. 자동 반영(스케줄) 또는
> 수동 배포(아래 6번)를 거쳐야 사이트에 나타납니다.

## 1. 구글 시트 구조 (이미 연결되어 있음)

> ✅ 이 사이트는 **이미 구글 시트에 연결되어 있습니다**
> (`scripts/sheets.config.json`의 `spreadsheetId`). 평소 콘텐츠 수정은 연결된 시트를
> 열어 편집하면 됩니다.

| 데이터       | 읽는 탭 (위→아래 순서로 이어붙임)  | 비고                                   |
| ------------ | ---------------------------------- | -------------------------------------- |
| People       | `People`                           |                                        |
| Projects     | `Projects`                         |                                        |
| Publications | `(수정 X) Pub-Manual` → `Pub-Form` | 기존 논문은 Manual, 새 논문은 폼 응답  |
| News         | `News-Form` → `News`               | 새 소식은 폼 응답, 예전 소식은 News 탭 |

- 탭 이름·폼 질문 제목은 `scripts/sheets.config.json`과 **정확히** 일치해야 합니다.
  탭 이름을 바꾸거나 폼 질문 문구를 고치면 이 파일도 같이 고쳐 주세요. (안 맞으면 배포
  로그에 경고가 뜨고, 해당 데이터는 직전 내용이 유지됩니다.)
- 손으로 편집하는 탭은 **첫 행이 아래 "컬럼 규격"의 헤더 이름과 똑같아야** 합니다.
  열 순서는 상관없습니다.
- 행 순서도 상관없습니다. 정렬은 사이트가 알아서 합니다.

#### 저자 이름 매칭 (`논문 표기 이름`)

Publications 탭의 저자 이름은 People 탭의 `영문명`·`한국어명`과 자동으로 대조되어,
일치하는 구성원의 `개인 홈페이지`로 연결됩니다. **국문 논문의 한글 저자명도 동일하게 연결됩니다.**

띄어쓰기·하이픈·대소문자 차이(`Sung-Eun Kim` = `Sungeun Kim`)는 자동 처리되므로 따로 적을 필요가 없습니다.
**로마자 표기 자체가 다른 경우에만** `논문 표기 이름`에 적어주세요.

예: 김평화(`Pyunghwa Kim`) 행의 `논문 표기 이름` 칸에 `Pyeong Hwa Kim` 입력

현재 연결되지 않고 있는 표기 예시 — 해당 구성원 행에 추가하면 바로 연결됩니다.

| ---------------------- | --------------------- |
| 김평화 `Pyunghwa Kim`  | `Pyeong Hwa Kim`      |
| 류다현 `Da Hyeon Ryoo` | `Dahyeon Ryu`         |
| 김남희 `Nam Hui Kim`   | `Nam Hee Kim`         |

#### 논문 블록 넣기

논문 제목·저자·유형을 눈에 띄게 보이게 하려면, 본문에서 원하는 **순서와 위치**에
아래 블록을 그대로 붙여 넣습니다. 일반 문단 사이에 여러 개를 넣어도 됩니다.

```text
:::paper
title: Understanding Productive Dialogue in Value-Laden Contexts through Hidden Markov Models
type: Full Paper
authors: Kyuwon Kim, Jeanhee Lee, Hyo-Jeong So
link: https://doi.org/10.0000/example
:::
```

- `title`만 필수입니다.
- `type`은 `Full Paper`, `Poster`처럼 필요할 때만 입력합니다. **저널 논문은 비워도 됩니다.**
- `authors`, `link`도 선택입니다. `link`가 있으면 제목을 클릭해 논문으로 이동합니다.
- `:::paper`부터 마지막 `:::`까지가 하나의 논문 블록입니다. 이 블록의 위치가 화면에
  표시되는 순서이므로 별도의 순번 관리가 필요 없습니다.

## 이미지 넣는 법

사이트의 모든 이미지(News 썸네일 · People 사진 · Projects 이미지)는 **저장소가 직접
보관**합니다. 시트에는 URL이 아니라 **저장소 내 경로**를 적습니다.

```
public/images/news/      ← News 썸네일
public/images/people/    ← 구성원 프로필 사진
public/images/projects/  ← 프로젝트 썸네일
```

**넣는 순서**

1. GitHub 저장소 → `public/images/` → 해당 폴더 → **Add file → Upload files**
   (브라우저에서 드래그앤드롭. 터미널 필요 없음)
2. 파일명은 알아보기 쉽게. News는 `날짜-키워드`, People은 `영문이름` 권장
   (예: `2026-07-aied.jpg`, `hyo-jeong-so.png`)
3. 시트의 `썸네일`/`사진`/`이미지 URL` 칸에 **`/images/폴더/파일명`** 형식으로 입력

   ```text
   /images/news/2026-07-aied.jpg
   /images/people/hyo-jeong-so.png
   ```

> ⚠️ 앞의 슬래시(`/`)를 빼먹으면 안 됩니다. `images/...`가 아니라 `/images/...`입니다.

**외부 URL도 여전히 동작하지만 권장하지 않습니다.** 예전에는 이미지가 아임웹
CDN(`cdn.imweb.me`)에 있었는데, 그쪽 구독이 끝나면 사이트 이미지가 전부 깨지기
때문에 2026년 7월에 60장을 저장소로 옮겼습니다. 같은 이유로 새 이미지도 저장소에
올려 주세요.

**용량은 신경 쓰지 않아도 됩니다.** 휴대폰·카메라 원본을 그대로 올려도, 배포할 때
`scripts/optimize-images.mjs`가 사이트에 나가는 사본을 자동으로 줄입니다.

- 가로 폭: People 사진은 **800px**, News·Projects 이미지는 **1200px**보다 크면 그 폭으로 축소
- 300 KB가 넘으면 더 효율적으로 다시 압축 (PNG 사진은 256색 팔레트로)
- 휴대폰 사진의 회전 정보(EXIF)를 반영해 세로 사진도 똑바로 나옴
- 파일 이름과 형식(jpg/png/webp)은 그대로라 시트의 경로를 고칠 필요 없음

저장소의 원본(`public/images/`)은 건드리지 않습니다. 다만 저장소가 너무 커지지 않도록
10 MB가 넘는 파일은 미리 줄여서 올려 주세요.

## 2. 시트를 링크 공개로 전환하기 (한 번만)

구글 시트 오른쪽 위 **공유(Share)** 버튼 → **일반 액세스(General access)** →
**"링크가 있는 모든 사용자(Anyone with the link)"**, 역할은 **뷰어(Viewer)**로 설정.

(이렇게 해야 API 키 없이 CSV로 읽을 수 있습니다. 편집 권한과는 무관하며,
읽기 전용 공개만 하는 것입니다. "파일 → 공유 → 웹에 게시"는 별도 기능이라
이것만으로는 동작하지 않습니다 — 반드시 위의 공유 대화상자에서 설정하세요.)

## 3. 시트 ID를 코드에 연결하기 (한 번만)

시트 URL이 `https://docs.google.com/spreadsheets/d/`**`여기가_시트ID`**`/edit...` 형태입니다.
이 `시트ID`를 `scripts/sheets.config.json`의 `spreadsheetId`에 넣습니다.

```json
{
  "spreadsheetId": "여기에_시트ID",
  "tabs": {
    "people": "People",
    "projects": "Projects",
    "publications": ["Pub-Manual", { "name": "Pub-Form", "columns": { "제목 (Title)": "title" } }],
    "news": [{ "name": "News-Form", "columns": { "뉴스 제목": "제목" } }, "News"]
  }
}
```

- 값이 문자열이면 탭 하나, 배열이면 여러 탭을 순서대로 이어붙입니다.
- `columns`는 **폼 질문 제목 → 컬럼 규격 헤더** 대응표입니다. 질문 제목이 이미 규격
  헤더와 같으면(예: `날짜`, `DOI`) 적을 필요가 없습니다.

이 파일을 커밋/푸시하면 이후 배포부터 시트 내용이 사이트에 반영됩니다.
(설정 전에는 저장소에 커밋된 기존 데이터가 그대로 쓰입니다.)

로컬에서 미리 확인하려면: `npm run sync` → `src/data/generated/*.json`이 갱신됨.

## 4. 구글 폼으로 입력받기 (News · Publications)

폼 응답 탭을 **sync가 직접 읽습니다.** 응답 탭을 다른 탭으로 옮기거나 합치는 수식,
관리자가 손으로 복사하는 작업은 필요 없습니다.

> 폼 설정 ⚙️ → 응답 → **"Ewha 계정으로 로그인 필요" + "응답 1회로 제한"** 을 켜 두세요.
> 승인 절차 없이 다음 배포에 바로 게시되기 때문입니다.

**사진이 있는 소식 — 관리자가 하는 일**

`News-Form` 탭 **오른쪽 끝에 `썸네일` 열을 한 번만 만들어 두고**(폼 응답 탭에 직접
열을 추가해도 폼은 계속 정상 동작합니다), 새 소식이 오면:

1. `뉴스 사진` 칸의 드라이브 링크를 열어 이미지를 내려받습니다
2. `public/images/news/`에 업로드합니다 (아래 "이미지 넣는 법" 참고)
3. **같은 행의 `썸네일` 칸**에 `/images/news/파일명.jpg`를 적습니다

`썸네일`을 비워 두면 기본 로고 이미지로 게시되고, 배포 로그에 "사진이 제출됐는데
썸네일이 비어 있다"는 경고가 뜹니다. 사진이 없는 소식은 **아무것도 안 해도 됩니다.**

**오타 수정·삭제**

- 수정: `News-Form` 탭의 해당 칸을 직접 고치면 됩니다.
- 삭제: 해당 응답 행을 지우면 다음 배포에서 내려갑니다.
- 같은 제목이 여러 행/탭에 있으면 **하나로 합쳐지고**, 비어 있지 않은 칸은
  **아래쪽(나중) 행·탭의 값이 우선**합니다. 즉 `News` 탭에 같은 제목이 있으면 `News`
  탭 값이 이깁니다. 헷갈리지 않게 한 소식은 한 곳에만 두세요.

### Publications 등록 폼 → `Pub-Form` 탭

| 폼 질문                          | 들어가는 곳  | 비고                                 |
| -------------------------------- | ------------ | ------------------------------------ |
| `논문 유형`                      | `type`       | `Journal`/`Conference`/`Book`        |
| `제목 (Title)`                   | `title`      |                                      |
| `저자 (Authors)`                 | `authors`    | 쉼표(,) 구분                         |
| `출판 연도 (Year)`               | `year`       |                                      |
| `게재처 (Venue)`                 | `venue`      |                                      |
| `색인 (Index)`                   | `index`      | 체크박스 `SSCI`/`SCOPUS`/`KCI`       |
| `DOI`                            | `doi`        | 전체 URL OK, `n/a`·`-`·`없음`은 무시 |
| `수상 (Award)`                   | `award`      |                                      |
| `출판 일자`, `Early Access 여부` | (사용 안 함) |                                      |

- **id는 sync가 자동으로 붙입니다.** `연도-유형첫글자-순번`(예: `2026-j-007`)이며,
  `Pub-Manual`의 같은 연도·유형 최대 번호 다음부터 폼 응답 순서대로 매깁니다.
  화면에는 안 보이고, 정렬(번호 큰 게 위)과 Projects의 `연관 논문 ID`에 쓰입니다.
- `pdf`·`acmdl`·`website` 같은 드문 항목이 필요하면 그 논문을 `Pub-Manual`에 직접
  적으세요. (`Pub-Manual`에 옮길 때는 `id`도 같이 적어 두면 번호가 고정됩니다.)
- 같은 제목의 논문이 두 번 있으면 배포 로그에 경고가 뜹니다. 하나를 지우세요.

### 새 폼을 연결하거나 질문을 바꿀 때

1. 폼 편집 화면 **응답 → 스프레드시트에 연결** → 이 스프레드시트의 새 탭으로 연결
2. `scripts/sheets.config.json`에서 해당 데이터의 탭 목록에 그 탭을 추가하고,
   질문 제목이 규격 헤더와 다르면 `columns`에 대응을 적습니다
3. 질문 문구를 나중에 고치면 `columns`의 왼쪽 값도 똑같이 고칩니다

## 5. (선택) 폼 제출 시 자동 배포

폼 제출 즉시 사이트를 갱신하려면, 시트에 연결된 **Apps Script**로 GitHub 배포를
트리거합니다.

1. GitHub에서 **Fine-grained Personal Access Token** 발급
   (Settings → Developer settings → Fine-grained tokens):
   - Repository access: `idlearning/idlearning.github.io`
   - Permissions: **Actions → Read and write**
2. 구글 시트 → **확장 프로그램 → Apps Script**에 아래 코드를 붙여넣습니다.
   `PROJECT SETTINGS → Script properties`에 `GH_TOKEN` = 발급한 토큰을 저장합니다.

```javascript
// 폼 제출 시 GitHub Actions 배포 워크플로우를 트리거합니다.
function onFormSubmit() {
  var token = PropertiesService.getScriptProperties().getProperty("GH_TOKEN");
  var url =
    "https://api.github.com/repos/idlearning/idlearning.github.io" +
    "/actions/workflows/deploy.yml/dispatches";
  UrlFetchApp.fetch(url, {
    method: "post",
    contentType: "application/json",
    headers: { Authorization: "Bearer " + token, Accept: "application/vnd.github+json" },
    payload: JSON.stringify({ ref: "main" }),
    muteHttpExceptions: true,
  });
}
```

3. Apps Script의 **트리거(⏰) → 트리거 추가** → 함수 `onFormSubmit`,
   이벤트 소스 **스프레드시트에서**, 이벤트 유형 **양식 제출 시**.

> 토큰은 구글 클라우드(Script Properties)에만 저장되며, 공개 사이트에는 절대
> 노출되지 않습니다.

## 자주 묻는 것

- **시트를 잘못 고쳐도 사이트가 깨지나요?** 어떤 데이터의 탭을 하나라도 읽지 못하면 그
  데이터 전체가 직전 내용으로 유지되고, 나머지는 정상 반영됩니다. 시트 ID가 비어 있으면
  저장소에 커밋된 데이터를 씁니다.
- **입력 실수는 어떻게 알 수 있나요?** GitHub 저장소 → **Actions** → 최근 배포 실행을
  열면 상단 **Annotations**에 경고가 모여 있습니다. 예: 날짜 형식 오류(해당 소식은
  게시 제외), 없는 이미지 경로, 드라이브 링크를 썸네일에 넣음, 알 수 없는 논문 유형,
  중복 논문, 존재하지 않는 `연관 논문 ID`, 폼 질문 제목이 설정과 다름. 경고가 있어도
  배포 자체는 진행됩니다.
- **반영 주기를 바꾸려면?** `.github/workflows/deploy.yml`의 `schedule: cron` 값을
  수정합니다(UTC 기준).
- **사진/이미지는?** 저장소 `public/images/`에 올리고 시트에는 `/images/...` 경로를
  적습니다. 위 "이미지 넣는 법" 참고.
